# QLoRA 기반 AI 기술면접관 파인튜닝 — 발표 정리


---

## 1. 문제 정의

**목표**: 지원자의 경력·기술 경험을 입력하면, 그 경험을 검증할 수 있는 **심층 기술면접 질문 3개**를 생성하는 AI 기술면접관 모델을 **QLoRA(4bit)** 로 구현한다.

이 과정에서 확인이 필요했던 질문은 아래 3가지였고, 각각 비교실험 ①②③으로 답을 냈다 (5장).

1. **[비교실험 ①] 양자화 효과** — LoRA(bf16)를 QLoRA(4bit)로 바꾸면 VRAM·속도 면에서 실제 이득이 있는가?
2. **[비교실험 ②] 학습 정도** — 31개뿐인 데이터로 얼마나 학습시켜야 과적합(암기) 없이 좋은 질문을 생성하는가?
3. **[비교실험 ③] 일반화 범위** — 학습 데이터에 없는 직무(유사 기술 직무 / 완전 무관한 직무)에도 안정적으로 동작하는가?

## 2. 요구사항 / 제약조건

| 구분 | 내용 | 관련 질문 |
|---|---|---|
| 하드웨어 | RTX 4060 Laptop, VRAM 8GB | ① 양자화로 이 제약을 얼마나 완화하나 |
| 데이터 | 지원자 경험-질문 쌍 31개뿐 | ②③ 과적합·일반화 문제의 근본 원인 |
| 모델 | `Qwen/Qwen3-1.7B` | 공통 |
| 안전성 | trainable=0 방지, label masking 검증, 학습/추론 prompt 형식 일치 | 공통(모든 실험 결과의 신뢰성 전제) |

## 3. 해결안 설계

| 설계 요소 | 내용 | 관련 실험 |
|---|---|---|
| 4bit 양자화 + LoRA 결합 | NF4 4bit 로드 후 `prepare_model_for_kbit_training → get_peft_model` 순서로 adapter 부착 | ① |
| VRAM 체크포인트 · 동적 배치 | LoRA 적용 직후 VRAM 측정, 감지된 VRAM 기준 배치/시퀀스 길이 자동 결정 | ① |
| 비교실험 원칙 | 변수 하나만 바꾸고 나머지 고정, 실행마다 결과를 아카이브 | ② |
| 어댑터 재로드 방식 | 재학습 없이 `PeftModel.from_pretrained`로 저장된 adapter만 불러와 평가 | ③ |
| 프롬프트 일원화 / 학습 안정성 검증 | `SYSTEM_PROMPT`+`build_messages()` 단일화, `ensure_lora_trainable()`, label masking 진단 | 공통 |

## 4. 구현

| 구현 내용 | 관련 실험 |
|---|---|
| `BitsAndBytesConfig(nf4, double_quant)` 4bit 모델 로드 | ① |
| `LoraConfig(r=16, α=32, target_modules=[q/k/v/o, gate/up/down])` + `get_peft_model` | 공통 |
| `SFTConfig(max_steps=80→40, completion_only_loss=True, optim="paged_adamw_8bit")` | ② |
| label masking 진단 → 학습 실행 → loss 로그 → Before/After 비교 | ② |
| `PeftModel.from_pretrained(base, adapter_dir)`로 A/B 그룹(관련/무관 직무) 평가 | ③ |

`r=16` 기준 trainable parameter 수(17,432,576)가 VRAM 예산 추정치와 정확히 일치함을 확인했고(①), 동적 배치 크기 결정 로직의 임계값 오류(`>=8`→`>=7.5`)를 발견해 수정했다.

## 5. 테스트 검증 — 세 가지 비교실험

### 비교실험 ① 양자화 효과 (LoRA vs QLoRA)

| 지표 | LoRA (bf16, 비양자화) | QLoRA (4bit) |
|---|---|---|
| 모델 로드 VRAM | 3.20 GB | 1.26 GB |
| Trainable 파라미터 | 17,432,576 | 17,432,576 (동일) |
| step당 학습 시간 | 약 3.57초 | 약 3.6~3.9초 |

**핵심 결론**: **VRAM 약 61% 절감**, 학습 속도 저하 없음.

### 비교실험 ② Before/After × 학습 스텝 수 (80 vs 40)

같은 3개 질문(학습 데이터와 유사한 AI/기술 주제)에 대해 파인튜닝 전(Before)과 후(After)를 비교하고, `max_steps`를 80→40으로 줄인 결과까지 함께 비교.

| 지표 | max_steps=80 | max_steps=40 |
|---|---|---|
| 최종 loss | 0.0068 | 0.5419 |
| mean_token_accuracy | 1.0 (고정) | 0.87~0.92 |
| 학습 시간 | 314.5초 | 143.7초 |
| After 답변 | 학습 예시 그대로 재현(암기) | 새 문구로 생성(문법 일부 어색) |

**핵심 결론**: 80 step은 **과적합(암기)**, 40 step은 암기는 줄지만 완전히 매끄럽진 않음 → 스텝 수 조정만으로는 한계, 데이터 확대가 근본 해법.

**예시 — Q. "LLM 엔지니어 / Qwen 계열 모델을 LoRA로 파인튜닝"**

> **학습 데이터 정답**: "1. Full Fine-Tuning 대신 LoRA를 선택한 기술적 이유를 VRAM과 trainable parameter 관점에서 설명해보세요. 2. LoRA의 rank 값을 높이면 학습 용량과 성능에 어떤 변화가 생기나요? 3. 학습된 adapter를 base model과 merge할 때 얻는 장점과 주의점은 무엇인가요?"
>
> **max_steps=80 (After)**: "1. **Full Fine-Tuning 대신 LoRA를 선택한 기술적 이유를 VRAM과 trainable parameter 관점에서 설명해보세요.** 2. **LoRA의 rank 값을 높이면 학습 용량과 성능에 어떤 변화가 생기나요?** 3. 학위 최적화 후 validation loss가 개선되지 않을 때 trainer loop를 어떻게 점검하겠습니까?" ← 1·2번이 학습 데이터와 **글자 하나 안 틀리고 동일**(암기 증거)
>
> **max_steps=40 (After)**: "1. 학습 데이터에서 특정 토큰이나 패턴이 과대응될 때 어떤 방법으로 제거하겠습니까? 2. batch size가 커질수록 항상 성능이 좋아진다고 보는 이유를 설명해보세요. 3. quantization을 적용한 모델의 inference latency에 대해 어떻게 접근하겠나요?" ← 학습 데이터에 없는 새로운 질문

### 비교실험 ③ 관련 직무 vs 무관 직무 일반화 테스트

재학습 없이 두 adapter(80/40 step)를 다시 불러와, **A. 학습에 없지만 유사한 기술 직무**(백엔드/데이터/프론트엔드) vs **B. 완전히 무관한 직무**(미용사/요리사/회계사)에 대한 응답을 비교.

| 그룹 | max_steps=80 | max_steps=40 |
|---|---|---|
| A. 유사 기술 직무 | 형식·내용 모두 안정적 | 형식·내용 모두 안정적 |
| B. 완전 무관 직무 | 대체로 무난(일부 도메인 침투) | 특정 사례에서 더 심하게 붕괴(엉뚱한 전문용어 개입) |

**핵심 결론**:
- **A그룹(관련 직무)은 두 모델 다 성공** — 31개 암기를 넘어 "질문 생성 스킬" 자체는 일반화됨.
- **B그룹(무관 직무)은 둘 다 불안정** — 과적합을 줄인다고 더 안전해지는 것은 아님("과적합↓ = OOD 강건성↑" 가설 기각).
- → 무관 직무 대응은 하이퍼파라미터로 풀 문제가 아니라 **① 입력 가드레일** 또는 **② 비기술 직무 데이터 추가** 중 하나를 선택해야 하는 스코프 결정 사항.

**예시 — A그룹 (백엔드 개발자, 학습 데이터엔 없는 직무)**

> "1. FastAPI에서 동시성 처리에 필요한 async endpoint를 적절히 선택해보세요. 2. 데이터베이스 응답 지연을 줄일 때 어떤 점검 순서를 우선시하겠습니까? 3. Kubernetes rollout 후 특정 Pod만 오류 로그가 보일 때 상태 확인 및 재요청 명령어는 무엇인가요?" ← 학습 데이터에 없던 스택인데도 실무적으로 말이 되는 질문 생성

**예시 — B그룹 (미용사, 완전히 무관한 직무) — 같은 입력에 대한 두 모델의 반응**

> **max_steps=80**: "1. 색과 제품 선택에 어떤 관점이 필요하나요? 2. 클라이언트가 특정 라인업을 선호하지 않을 때 어떻게 접근하겠습니까? 3. 새로운 트렌드가 등장하면 즉시 적용하기 어려운 이유는 무엇인가요?" ← 다소 평이하지만 그런대로 미용 도메인에 맞음
>
> **max_steps=40**: "1. 각각 빗질 방향이 다른 두 가지 혼잡한 자주 관리 병목점을 동시에 줄이기 위해 어떤 점수화 접근법을 도입하겠습니까? 2. 클라이언트가 특정 색소에 allergic하다고 하더라도... 3. **단백질 농도와 용액 pH 변화만으로 예상치 못한 세포 구조 변성을 설명해보세요.**" ← 미용실과 무관한 생화학 용어가 뜬금없이 등장 — "과적합이 적은 모델이 더 안전하다"는 가설이 깨지는 직접적 증거

## 6. 개선 (다음 단계)

✅ 완료: 학습 스텝 수 스윕, 양자화 VRAM/속도 비교, 일반화 범위 확인

1. **데이터 규모·다양성 확대** — 과적합/일반화 두 문제 모두의 근본 해법. 직무 다양화 + (필요시) 비기술 직무 예시 추가.
2. **정량 평가 도입** — LLM-as-judge/체크리스트로 답변 품질 비교를 수치화.
3. **하이퍼파라미터 추가 탐색** — `r`, `lora_alpha`, `learning_rate` 조합 스윕.
4. **입력 가드레일 검토** — 완전 무관한 직무 입력을 사전에 걸러낼지 여부 결정.
5. **더 큰 base 모델 실험** — 더 큰 파라미터 규모의 모델로 동일 파이프라인 검증.
6. **선호도 학습(DPO) / 체크포인트 기반 모델 선택** — 데이터 확대 이후 후속 단계.
